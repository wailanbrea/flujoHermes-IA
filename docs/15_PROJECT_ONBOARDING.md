# Project onboarding

1. Obtain explicit authorization for one project and record its exact path.
2. Back up configuration; never copy `.env`, credentials, customer data, or
   production dumps.
3. Audit stack, versions, architecture, tests, Git state, size, and protected
   paths read-only.
4. Copy the documentation templates and customize `AGENTS.md`.
5. Create a single task contract with narrow allowed and forbidden scope.
6. Create an isolated branch/checkpoint and test database.
7. Select only the required skills and tools.
8. Run the baseline quality gate before modifying code.
9. Execute one small task, validate, review diff, report metrics, and hand off.
10. Expand scope only after the pilot proves reproducible and safe.

Projects under `C:\xampp\php\www` and `C:\xampp\htdocs` remain unauthorized.
